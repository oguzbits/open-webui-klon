# Bedrohungsmodell (STRIDE)

Stand: Teilprojekt 4a. Wird in jedem Teilprojekt fortgeschrieben. Maßstab und Maßnahmenkatalog:
[Spec Abschnitt 6.1](superpowers/specs/2026-10-09-open-webui-nestjs-design.md).

## Werte

Nutzerkonten und Sessions, Chat-Inhalte, hochgeladene Dokumente und Embeddings, API-Keys der Nutzer,
Provider-Keys der Admins, die Verfügbarkeit der API und der Modell-Anbieter (Kosten).

## Akteure und Vertrauensgrenzen

| Akteur / Quelle                              | Vertrauen      | Grenze                          |
| -------------------------------------------- | -------------- | ------------------------------- |
| Angemeldeter Nutzer                          | gering         | Browser -> Caddy -> API         |
| Admin                                        | erhöht         | konfiguriert Anbieter und Hosts |
| Sprachmodell-Ausgabe, Tool-Ergebnisse        | **unvertraut** | API <-> Anbieter                |
| Hochgeladene und abgerufene Dokumente        | **unvertraut** | Upload, `SafeFetchService`      |
| Externe Anbieter (Ollama, OpenAI-kompatibel) | teilvertraut   | ausgehende Verbindungen der API |
| Postgres                                     | vertraut       | internes Docker-Netz `backend`  |

| ---------------------- | ------------------------------------------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| Spoofing               | Konto-Übernahme, Brute Force                                                                           | Argon2id, Rate Limit, Session-Rotation (1); Cookie `httpOnly`/`SameSite=Lax`, Token nur als SHA-256, CSRF-Header (1); Rate Limit global (0)                                                                                                                                                                                                                                                                                          |
| Spoofing               | Gestohlener Session-Cookie oder Key                                                                    | Session und Key sofort widerrufbar, Sperren/Löschen/Passwortwechsel löschen Sessions, Keys nur als Hash (1); Klartext eines neuen Schlüssels nur im Speicher des Dialogs, nach dem Schließen verworfen (1b)                                                                                                                                                                                                                          |
| Tampering              | Nutzer- oder Schlüsselname mit HTML in der Verwaltung (XSS)                                            | React escaped, kein `dangerouslySetInnerHTML`, Test mit `<img onerror>` in Nutzerliste und Schlüsselliste, Handprobe im Browser (1b)                                                                                                                                                                                                                                                                                                 |
| Tampering              | Manipulierte Requests, Mass Assignment                                                                 | ValidationPipe mit Whitelist (0); Origin-Prüfung für schreibende Requests (0)                                                                                                                                                                                                                                                                                                                                                        |
| Tampering              | Audit-Einträge nachträglich ändern                                                                     | Append-only-Trigger auf `audit_log` (0); gilt nur gegen den Anwendungscode, solange die API als Eigentümer-Superuser verbunden ist (Rollentrennung: BACKLOG)                                                                                                                                                                                                                                                                         |
| Repudiation            | Wer hat was geändert?                                                                                  | Audit-Log mit Request-ID (0), Nutzung ab (1)                                                                                                                                                                                                                                                                                                                                                                                         |
| Information disclosure | IDOR, fremde Daten lesen                                                                               | Abfragen in SQL nach Besitzer/ACL begrenzt, Test pro Endpunkt (jedes)                                                                                                                                                                                                                                                                                                                                                                |
| Information disclosure | Konten erraten (Enumeration)                                                                           | gleiche Antwort und Rechenzeit für unbekannte E-Mail, falsches Passwort, gesperrtes Konto; Rate Limit je E-Mail und IP (1)                                                                                                                                                                                                                                                                                                           |

| Information disclosure | Zugriff auf fremde Chats (IDOR)                                                                        | Jede Abfrage in SQL mit `userId`; fremde und unbekannte Chats, Nachrichten und `parentId` sind `404` (3a, Tests je Route)                                                                                                                                                                                                                                                                                                            |
